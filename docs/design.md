# Sedi Review の仕組み

AI が書いた大きな差分を、意味のセクションに分けて人が読むための道具です。
この資料は、中の作りを説明します。使い方は [README](../README.md)、命令の一覧は [CLI](cli.md) にあります。

## 1. 全体の形

- Go の実行ファイル 1 つで動きます。Go の外部のライブラリは使いません。画面は素の HTML/JS/CSS で、実行ファイルに埋め込みます
- 画面の色分けにだけ、第三者のコード Prism 1.30.0（MIT）を `web/static/vendor/` に同梱しています（11 章）
- `sedi-review open` は 127.0.0.1 に一時サーバーを立て、URL を出します。ポートは既定で 0（OS が空きを選ぶ）です。ブラウザは `--open` を付けたときだけ開きます
- 画面が開いている間は、SSE の接続が続きます。接続が 0 になってから 30 秒でサーバーは終わります。一度も開かれないまま 10 分たっても終わります。Ctrl+C でも止まります
- エージェントは、同じ実行ファイルの子コマンドで読み書きします。サーバーが動いていれば HTTP で、動いていなければ保存のファイルに直接書きます
- エージェント向けの手順（skill、`skills/` の下の `sedi-review` と `sedi-review-init`）も実行ファイルに埋め込みます。`sedi-review skill install` が、
  実行ファイルと同じ版の手順を各エージェントの置き場所に写します。命令と手順の版がずれないためです。
  利用者が `--agent` で選んだ先にだけ写し、手で直したものは `--force` が無い限り置き換えません

## 2. 初期化と設定

- 使う前に、リポジトリで `sedi-review init` を 1 回実行します。初期化していないリポジトリでは、`open` などの命令は止まります。道具が黙ってリポジトリにフォルダを作らないためです
- `init` がすること
  - 保存のフォルダ `.sedi-review/` を作り、中に `*` の 1 行の `.gitignore` を置く。フォルダが自分を git から外すので、リポジトリの `.gitignore` は書き換えない
  - 設定のファイル `.sedi-review.json` を書く。追跡して共有するためのもので、コミットするかは利用者が決める。既にあれば書き直さない（`--force` で書き直す）
- 設定の形:

  ```json
  { "base": "main", "twoDot": false, "rule": "unity", "rules": { "unity": [":(exclude,glob)**/*.cs.meta"] } }
  ```

  | 項目 | 意味 |
  |---|---|
  | `base` | `open` の既定の比べる元。`init` で省くと `main`、無ければ `master` |
  | `twoDot` | 既定の比べ方を `A B` にするか |
  | `rule` | 既定のルール |
  | `rules` | 名前を付けたルール（pathspec の並び） |

  組み込みのルールは 2 つです。`unity` は `:(exclude,glob)**/*.cs.meta` で、`all` は何も外しません。

## 3. 比較と対象

- 比べるのは、コミットかブランチの 2 点です。作業ツリーの未コミットの変更は対象にしません
- `--base`（省くと設定の `base`）と `--target`（既定 `HEAD`）で指定します。既定は `A...B`（分かれた点から B まで）で、`--two-dot` で `A B` になります
- 開いた時点でコミットのハッシュに解決し、更新するまで固定します
- 対象は pathspec で決めます。`--rule` で名前を付けたルールを選び、`--` の後に足せます
- 差分は `git diff <base>...<target> -- <pathspec>` をそのまま呼びます。オプションは足しません
  - 前後の行の数、差分の作り方、名前の変更の検出は、利用者の git の既定と設定に従います
  - `diff.noprefix` `diff.mnemonicPrefix` `diff.srcPrefix` `diff.dstPrefix` は、パスの前置きを取り除くために読みます
  - 色の制御文字や外部の差分ツールの出力など、標準の形でない出力は解析せず、疑われる設定の名前を出して止めます

## 4. 差分の解析

- `diff --git` ごとに 1 ファイルです。見出しの行（`new file mode` `deleted file mode` `rename from/to` `index` `---` `+++` `Binary files ... differ` など）を読み、`@@` から hunk を読みます
- hunk の終わりは、`@@` の行数で数えます。空の文脈の行（`diff.suppressBlankEmpty`）も扱います
- パスの引用（`core.quotePath` による `"..."` と八進の書き方）は、git の書き方どおりに解きます
- 中身の差分が無い変更（純粋な名前の変更、権限だけの変更）は出しません
- バイナリは `Binary files` の行で見分け、`index` 行の blob の ID を持ちます

## 5. hunk の ID

- `SHA-256( パス + "\n" + 本文の各行 )` の先頭 16 桁（16 進）です
  - パスは変更後の側（削除なら変更前の側）
  - 本文は、`+` `-` 空白の記号を含めた各行と、`\ No newline at end of file` の行
  - `@@` の行番号と、その後ろの関数の文脈の文字列は入れない。上の方の変更で行がずれても、ID は変わりません
- 同じファイルに同じ値が出たら、何番目かの番号を足して作り直します
- 人が見分けるための通し番号 `h1, h2, ...` も振ります。参照は常に ID で行います

## 6. 付け先

メッセージは次のどれかに付けます。

| 種類 | 持つもの |
|---|---|
| 全体 | なし |
| セクション | セクションの鍵（名前を ` / ` でつないだ道筋） |
| ファイル | パス |
| hunk | パス、hunk の ID |
| 行 | パス、hunk の ID、変更前か後か（`old` / `new`）、hunk の中の位置（始めと終わり）、その行の中身の写し |

見つからない付け先は「付け先なし」として出します。エージェントは `reattach` で付け直せます。

## 7. セクション

エージェントが JSON で渡します（`sedi-review sections set`）。

```jsonc
[
  {
    "name": "セーブの鍵",
    "intent": "鍵をプロジェクトごとに作り直す",
    "checks": ["既存のセーブが読めるか"],
    "files": ["Assets/App/Save/KeyStore.cs"],          // そのファイルの全部
    "hunks": ["3f9a1c0d2b4e5f60"],                      // 他のファイルの一部の hunk
    "lines": [{ "path": "Assets/App/Save/SaveSystem.cs", "side": "new", "from": 1, "to": 120 }],  // hunk の中の行
    "children": []
  }
]
```

- 並びの順を、読む順とします。1 つの hunk や行が、複数のセクションに入ってかまいません。入れ子にできます
- `lines` は、ファイルの行番号（`side` は `new` が既定、消えた行なら `old`）で範囲を書きます。新しく足したファイルは丸ごと 1 つの hunk になるので、型やメソッドごとに分けるときに使います
  - 道具は、範囲の行を含む hunk ごとに、最初と最後の該当する行の間を hunk の中の範囲（0 から数えた位置）として持ちます。間にある削除の行も入ります
  - 同じセクションで、丸ごと入る hunk と範囲が重なれば、丸ごとの方だけを持ちます
- 兄弟で名前が重なるもの、存在しないパスや ID、変更の無い行の範囲は、取り込む前に誤りとして返します
- どのセクションにも入らない hunk とバイナリのファイルは、「未分類」に出します。範囲で一部だけが入った hunk は、どの範囲にも入らない残りの行（変更の行を含む部分だけ）を「未分類」に出します

## 8. 確認済み

- 作業者が読んだことのチェックです。正しいかどうかの判定ではありません
- 付けられるのは、ファイルとセクションだけです。ファイルの印とセクションの印は互いに関係しません（親と子のセクションも）
- 付けたときの中身の指紋を、一緒に保存します
  - ファイル: その hunk の ID の並び（バイナリは blob の ID）
  - セクション: 属する hunk の ID、hunk の中の範囲、ファイルの指紋の集まり
- 名前が変わると鍵が変わるので、印は外れます。更新で指紋が変わったものも外します
- エージェントは外すことだけができます（`unmark`）。付けることはできません
- 画面には、確認済みのセクションの数とファイルの数を出します

## 9. メッセージ

- スレッドです。種類は 指示・質問・再考・その他。状態は 未送付・送付済み・返事あり・閉じる で、スレッドごとに持ちます
- 作業者のメッセージは、送るまでは編集と取り消しができます。送ったあとは編集できません
- エージェントは、返事のほか、自分からスレッドを始められます
- 渡し方
  - 個別の「コピー」: そのスレッドの全文、付け先、返事のしかたを、貼るための文にしてクリップボードへ入れます
  - 一括の「コピー」: 全スレッドを保存の場所の `exports/` に書き出し、そのパスと返事のしかたをクリップボードへ入れます
  - どちらも、含めた未送付のメッセージを送付済みにします
- 待ち受け: エージェントが `sedi-review wait` を動かしている間、画面に「送る」が出ます。押したスレッドは待ち受けに渡す予定になり、次の `wait` が受け取ります
  - `wait` は `GET /api/agent/poll` で最大 25 分待ちます。渡すものがあれば返し、無ければ時間切れを返します
  - 書き出しに成功したら送付済みにします。失敗したら、次の `wait` で渡し直します
- 種類ごとにエージェントがすることは、渡す文に毎回書きます

## 10. 保存

`<リポジトリ>/.sedi-review/reviews/<レビュー ID>/` に保存します。

- リポジトリごとに分かれるので、プロジェクトの間で競合しません
- リポジトリを消せば一緒に消えます。掃除はこのフォルダを消すだけです。`git clean -fdx` でも消えます
- worktree ごとに別のレビューになります

| ファイル | 中身 |
|---|---|
| `review.json` | リポジトリのパス、指定（base・target・起点・ルール・pathspec）、解決したコミット |
| `sections.json` | セクション |
| `marks.json` | 確認済みと指紋 |
| `threads/<ID>.json` | スレッド 1 つ |
| `exports/` | 一括で書き出した文 |
| `server.json` | 動いているサーバーのポート・PID・合言葉 |

- レビュー ID は、指定（base・target・起点・ルール・pathspec）から作ります。同じ指定なら同じレビューに戻ります
- エージェント向けの命令は `--repo` でリポジトリを受け取ります。渡す文には `--repo` を毎回書きます
- 書き込みは、一時ファイルに書いてから名前を変えます

## 11. 安全

- 127.0.0.1 だけで待ち受けます。`Host` が `127.0.0.1:<port>` か `localhost:<port>` でなければ断ります
- 書き込みの要求は、画面からなら、`Origin` が同じであることと独自の見出しを求めます。エージェントの CLI は、`server.json` の合言葉を見出しに付けます
- blob（ファイルの中身）は、画像（PNG・JPEG・GIF・WebP・SVG）と音声（WAV・Ogg・Opus・MP3・M4A・AAC・FLAC）の形式だけを、拡張子で決めて返します
  - `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'` を付けます。SVG は `<img>` で出します
  - 返せるのは、その差分のそのファイルの、変更前か変更後の blob だけです
  - 音声の早送りのために、範囲の要求（Range）に応じます
- 外へは何も送りません。他のツールの設定を書き換えません
- Windows では、子プロセスに窓を出しません

## 12. 画面

- 左の列: セクションの木（全体・未分類を含む）と、確認済みの数
- 中の列: 「ファイル」と「メッセージ」のタブ。ファイルの一覧は、既定で「選択中のセクションのみ」です（全体を選んでいればすべて、未分類なら未分類のファイル）。「すべて」に切り替えられます
- 右: 選んだセクションかファイルの hunk。ファイルは見えたときに読み込み、200 件ずつ出します。セクションに範囲で入った hunk は、その範囲の行だけを出し、範囲の外の行は「ここに出さない n 行」とまとめます。未分類でも同じように、残りの範囲だけを出します
- 行の番号を押すと行を選べます（Shift で範囲）。hunk・ファイル・セクション・全体にもメッセージを付けられます
- 画像と音声のファイルは、変更前と変更後を並べて出します。音声はブラウザの再生の部品で、押すまで読み込みません。ブラウザが再生できない形式なら、その旨を出します（AIFF などは、ブラウザが扱えないので対象にしません）
- 色分け: 同梱の Prism を使います
  - `vendor/prism.js` は、jsDelivr の prismjs@1.30.0 の core と言語のファイルを、手を加えずにつないだものです。許諾は `vendor/PRISM-LICENSE.txt` です
  - 自動の色分けは切り（`manual`）、hunk の変更前と変更後をそれぞれまとめて色分けしてから、行に分け直します
  - 20,000 行を超える hunk と、対応しない拡張子は色分けしません（4,637 行の C# で、色分けと行への分け直しに約 90 ms）
  - 言語は拡張子で決めます（C#・HLSL・Go・JS・CSS・HTML/XML・JSON・YAML（Unity の .asset など）・Markdown・Bash）
- 上の欄の「ヘルプ」で `help.html` を別のタブに開きます。使い方とライセンスを出します
  - Sedi Review 自体は MIT License（`LICENSE`）です。対象はコードだけで、道具を使って作ったものは対象にしません。`LICENSE` は実行ファイルに埋め込み、`/LICENSE.txt` で返します
  - 同梱している第三者のソフトウェアは、Prism（MIT）と Go の標準ライブラリ（BSD 3-Clause）です。許諾の全文は `vendor/` のファイルから読み込みます（`vendor/GO-LICENSE.txt` は Go の配布物の `LICENSE` を写したもの）
- 開発中は、環境変数 `SEDI_REVIEW_WEB` に `web/static` を指すと、埋め込みではなくディスクの画面を出します
